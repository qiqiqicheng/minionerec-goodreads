# SFT 训练前差距、风险和模块待办

更新日期：2026-05-13

## 当前判断

现在已经不是“没有 SFT 代码”的状态，而是“可以准备做很小的 SFT smoke run，但还不适合直接开正式 SFT 训练”的状态。

已经具备的部分：

- RQVAE 主流程已经跑完：`goodreads.emb-bge.npy`、`goodreads.index.json`、`goodreads.item.json`、`train.csv/valid.csv/test.csv` 都已经存在。
- 当前处理后的规模是 295,730 条 next-item row，11,524 个 user，6,125 个 item；比论文 Appendix B 里的单域训练行数更大，不能直接照搬 batch/epoch 预期。
- SFT 骨架已经有：`SFTDataModule`、`SFTModule`、`train_sft.py`、`train_sft.yaml`、`data/sft.yaml`、`model/sft_*.yaml`。
- 当前 SFT 数据任务已经覆盖 4 类：SID history -> next SID、SID -> title、title -> SID、title history -> next SID。

核心缺口：

- 配置还不是本机可直接训练配置：base model 路径是 macOS 路径，默认 trainer 还是 CPU，SFT 没有 Makefile target。
- 训练策略还没定清楚：`new_token_only` 只能学习新增 SID token embedding，不能真正让 LLM 学推荐模式；`qlora` 更像正式 SFT，但需要确认新增 SID token embedding 会被训练。
- 目前只有 loss-only SFT，没有推荐生成评估；可以训练，但训练完无法判断 recommender 质量。
- SID artifact 是 warning 状态，碰撞靠 fallback token 解决；这不一定阻塞首轮 SFT，但必须在记录和评估里明确。

## P0：正式 SFT 训练前必须完成

### 1. 修正 SFT 的本机运行配置

风险：现在 `src/minionerec_goodreads/configs/data/sft.yaml` 里 `pretrained_model_name_or_path` 指向 `/Users/avalanche/hf-download/llm/Qwen2.5-1.5B-Instruct`，在当前 Linux 机器上不可用；`train_sft.yaml` 默认加载 `trainer: default`，而 `trainer/default.yaml` 是 CPU。

需要改/增：

- `src/minionerec_goodreads/configs/data/sft.yaml`
  - 不要把本机绝对模型路径写死到通用配置里。
  - 建议通过 `configs/local/default.yaml` 或 Hydra override 传入本机 Qwen2.5/Qwen3 模型路径。
- `src/minionerec_goodreads/configs/trainer/sft_gpu.yaml` 或 `configs/experiment/sft_goodreads_*.yaml`
  - 设置 `accelerator: gpu`、`devices: 1`、`precision: bf16-mixed`。
  - 单卡 24GB 先从小 batch 开始，不要直接沿用论文的 H100 配置。
- `Makefile`
  - 增加 `sft-smoke` 和 `sft` target，继续保持项目约定的 `uv + Makefile` 工作流。

建议第一轮 smoke 配置：

- `model=sft_new_token_only` 或修好后的 `model=sft_qlora`。
- `data.max_train_samples=512`、`data.max_valid_samples=128`、`data.max_test_samples=128`。
- `trainer.max_epochs=1`，先只验证 tokenizer、dataloader、forward/backward、checkpoint 能跑通。

### 2. 决定 SFT 训练模式：不要把 `new_token_only` 当成完整 SFT

风险：当前默认 `model: sft_new_token_only` 只解冻新增 SID token 的 embedding 行。这个阶段适合做 SID token warmup，但它基本不会改变 Transformer 主体的推荐建模能力。如果用它跑完以后直接报告 MiniOneRec SFT 效果，会被问住。

需要改/增：

- `src/minionerec_goodreads/models/sft.py`
  - 启动时打印 trainable parameter 数量、比例、训练模式。
  - 对 `new_token_only` 打印新增 token 范围和 input/output embedding 是否都被 row-mask。
  - 对 `qlora` 检查新增 SID token embedding 是否真的 `requires_grad=True`。
- `src/minionerec_goodreads/configs/model/sft_qlora.yaml`
  - 如果走 QLoRA，需要保证 LoRA 权重和新增 SID token embedding 都被训练。
  - 注意 PEFT 默认可能只训练 LoRA adapter，不一定训练 resize 后的新 embedding 行。

推荐路线：

1. 先跑 `new_token_only` smoke/warmup，验证 SID token 能被模型稳定输出。
2. 再跑 QLoRA 正式 SFT，让模型主体通过 LoRA 学推荐和对齐任务。
3. 24GB 显存下优先 QLoRA + bf16 + gradient checkpointing；full finetune 暂时不要作为首选。

### 3. 加 SID tokenizer 原子性检查

风险：当前 SID 是字符串拼接，例如 `<a_60><b_20><c_103><d_9>`；`tokenizer.add_tokens` 理论上会让每个 `<a_*>`、`<b_*>` 作为 added token，但必须用真实 Qwen tokenizer 验证。当前 artifact 里 SID token length 是 4 到 5，不是固定 3；代码和评估都不能写死 SID 长度。

需要改/增：

- `src/minionerec_goodreads/utils/sft.py`
  - 增加一个 smoke check：随机抽若干 item，encode SID string，确认 token ids 数量等于 `goodreads.index.json` 中的 token 数量。
  - 检查 decode 后是否能恢复相同 SID token 串。
- `tests/` 或脚本级 sanity check
  - 覆盖普通 4-token SID 和 fallback 后的 5-token SID。

必须确认：

- 新增 SID token 数量与 `goodreads.index.json` 中出现的 token 集一致，目前小样本检查显示是 757 个。
- 任何 prompt 中的 SID 都不会被拆成普通子词。
- eos/pad 设置正确，label mask 只训练 response 部分。

### 4. 做 SFT 数据样本和长度统计

风险：`SFTDataModule` 会一次性读入 CSV，并为 seq/item/fusion 任务构造样本。数据量本身可接受，但 title history 可能很长；当前 `TokenizedSFTDataset` 是拼好完整 prompt 后再 `input_ids[-max_length:]` 左截断，可能把 instruction 或早期历史截掉。这样能训练，但 prompt 分布不够可控。

需要改/增：

- `src/minionerec_goodreads/dataset/sft_dataset.py`
  - 在 setup 结束后打印每个 split、每个 task 的样本数。
  - 增加 token length 统计：p50/p90/p95/p99/max、超过 `max_length` 的比例。
  - 最好先按 history item/title 数量或 token budget 截断，再格式化 prompt。
- 新增一个小脚本或 datamodule 方法
  - dump 3-5 条 decoded prompt/label 到日志，人工确认训练目标没有错。

需要重点检查：

- `seq_sid_to_sid` 是否只输出目标 SID。
- `title_history_to_sid` 是否没有把目标 title 泄露进输入。
- `sid_to_title` / `title_to_sid` 的训练样本覆盖范围是否符合当前实验口径。

### 5. 明确任务混合比例和验证口径

风险：当前训练、验证、测试都会混合 seq、item alignment、fusion 三类任务。`val/loss` 是混合 loss，不是纯推荐 loss，更不是 HR/NDCG。用这个 loss 选 checkpoint 可以作为工程上的 warmup 指标，但不能作为推荐效果结论。

需要改/增：

- `src/minionerec_goodreads/dataset/sft_dataset.py`
  - 给 batch 带上 `task` 或 `task_id`，支持按 task 统计 loss。
  - 或者拆出 recommendation-only val dataloader。
- `src/minionerec_goodreads/models/sft.py`
  - log `val/loss_seq_sid_to_sid`、`val/loss_title_history_to_sid`、`val/loss_sid_to_title`、`val/loss_title_to_sid`。
- `src/minionerec_goodreads/configs/callbacks/sft.yaml`
  - 先考虑 monitor 推荐相关 loss，而不是所有任务混合后的 `val/loss`。

建议：

- 第一轮正式训练可以保留混合任务，但 checkpoint 选择至少要单独看 recommendation task loss。
- 后续报告指标必须用生成式推荐指标，不能只报 SFT loss。

## P1：能开跑后尽快补，否则结果不可解释

### 6. 增加生成式推荐评估链路

风险：现在 `src/minionerec_goodreads/scripts/eval.py` 只是 Lightning `trainer.test`，本质是 loss-only eval。MiniOneRec 论文结果看 HR@K/NDCG@K；如果没有 generation-time eval，就无法判断 SFT 是否真的会推荐。

需要新增：

- `src/minionerec_goodreads/scripts/sft/eval_sft.py`
  - 加载 SFT checkpoint、base tokenizer、SID index。
  - 对 valid/test 的推荐任务构造 prompt。
  - 生成 top-K SID，映射回 item_id。
  - 输出 HR@3/5/10、NDCG@3/5/10、invalid rate、duplicate rate。
- `src/minionerec_goodreads/utils/sft_decode.py` 或类似模块
  - SID string -> item_id。
  - item_id -> SID string。
  - 处理 fallback 5-token SID。
- `src/minionerec_goodreads/metrics/rec.py` 或简单函数
  - 实现 HR/NDCG/MRR。

### 7. 增加 constrained decoding / SID trie

风险：无约束生成时模型很可能输出非法 SID 字符串、半截 token、重复 item 或不存在的 code path。SFT loss 可以下降，但生成推荐时全是无效输出。论文的 RL 也默认 constrained decoding；如果这里不补，后续 GRPO reward 会非常脏。

需要新增：

- 基于 `goodreads.index.json` 构造 SID token trie。
- 每一步只允许当前 trie 节点的合法 next token。
- beam search 返回合法且去重的 item_id。
- 记录 invalid/duplicate 的统计，即使 constrained decoding 后理论上 invalid 应为 0。

模块建议：

- `src/minionerec_goodreads/utils/sid_trie.py`
- `src/minionerec_goodreads/utils/sft_generation.py`
- `src/minionerec_goodreads/scripts/sft/eval_sft.py`

### 8. 检查 SID artifact 健康状态和统计口径

风险：`data/processed/rqvae/goodreads.sid_health.md` 当前是 WARNING，报告 raw code path collision；`notes/rqvae_eda.md` 里也记录 SID health warning，但 collision 数值和 health report 不完全一致。虽然 dedup fallback 让每个 item 都有唯一 SID，但这会把“语义码碰撞”隐藏成额外 token 问题。

当前必须写进实验口径：

- 当前 catalog 是 6,125 items。
- SID index 覆盖 6,125 items。
- SID token length 不是固定 3，目前是 4 到 5。
- raw code path 有碰撞，最终靠 fallback token 保证 item-level 唯一。
- 这是 transductive item vocabulary，不是严格冷启动。

需要改/增：

- 统一 `goodreads.sid_health.md` 和 `notes/rqvae_eda.md` 的 SID collision 统计口径。
- 在 SFT 启动日志里打印 SID item 数、unique SID path 数、fallback item 数、最大 SID token length。
- 如果未来重新选 RQVAE ckpt，先比较 collision，再开 SFT。

### 9. 处理 valid/test 中的新 target item 和新 user

风险：当前 split 是全局 chronological，不是 per-user leave-one-out。`notes/rqvae_eda.md` 显示 valid/test 有新 target user，也有 36/47 个 target item 没作为 train target 出现。由于 item metadata/SID 是全 catalog transductive 构造，这不是严格 item 冷启动，但 SFT 推荐任务确实没见过这些 item 作为 target response。

需要明确：

- 评估是 roll-forward chronological evaluation。
- valid/test history 可能包含更早的 valid/test 事件，但每条样本的 target 仍在 history 之后。
- 新 item target 的表现要单独看，否则整体指标可能掩盖模型不能生成少见 item 的问题。

需要新增评估切片：

- seen-target item vs new-target item。
- seen user vs new user。
- history length bucket。
- review-sourced text item vs description-sourced item。

### 10. 增加 checkpoint/export 规范

风险：Lightning checkpoint 本身不等于可复现的 HF 模型。SFT 时 tokenizer 是从 base model + `goodreads.index.json` 动态 rebuild 的，如果只保存 `.ckpt`，后续 eval/RL/推理容易因为 tokenizer 或 SID index 不一致而出错。

需要新增：

- 训练结束保存：
  - augmented tokenizer。
  - SID index。
  - item payload path/hash。
  - model/adapter 权重。
  - config resolved yaml。
- 对 QLoRA，明确保存 adapter 还是 merge 后模型。

模块建议：

- `src/minionerec_goodreads/scripts/sft/export_sft.py`
- 或在 `train_sft.py` 训练结束后增加可选 export callback。

## P2：复现 MiniOneRec 完整 SFT 配方时再补

### 11. 补全论文里的 alignment tasks

当前已有任务：

- Generative retrieval：SID history -> next SID。
- Asymmetric item prediction 的一部分：title history -> next SID。
- SID-title mapping：SID -> title、title -> SID。

还缺或不完整：

- item description reconstruction：SID -> description、description -> SID。
- user preference summarization：SID/user history -> preference summary。
- 更严格的 asymmetric item prediction：SID-only history -> title next item。

建议取舍：

- 首轮 SFT 不必立刻做 preference summarization，因为需要额外 pseudo label，成本较高。
- 可以优先补 description -> SID / SID -> description，因为 `goodreads.item.json` 已经有 description/review fallback 文本。
- 如果补 open-ended description 生成，要单独控制 loss 权重，避免自然语言长文本任务淹没推荐 SID 任务。

### 12. 重新设计 item alignment 样本覆盖范围

风险：当前 `build_item_task_samples` 使用每个 split 的 target item 集合。这样 train alignment 只覆盖 train target items；valid/test alignment 会用 valid/test target items 构造 loss。这不一定错，但口径要清楚。

可选方案：

- 保守方案：训练阶段只用 train target items 做 item alignment，避免额外利用 valid/test target metadata。
- Transductive catalog 方案：训练阶段对全 catalog item 做 SID-title/description alignment，并明确说明 item metadata 全量可用，冷启动不在当前实验范围内。

推荐：当前项目已经是全 catalog 生成 embedding 和 SID，可以采用 transductive catalog 方案，但必须在 notes 和实验报告里说明。

### 13. 给 SFT 加基线和 sanity baseline

风险：没有 baseline 时，即使 SFT 跑通也不知道是否有效。

建议至少加：

- popularity top-K baseline。
- random valid SID baseline。
- 不训练 Qwen-SID zero-shot / base model generation。
- `new_token_only` vs QLoRA 对比。

这些能帮面试时讲清楚：LLM + SID 到底比 popularity 或随机强多少。

## 最可能踩的坑

1. `new_token_only` 跑得动但效果很弱：它更像新增 SID token warmup，不是完整推荐 SFT。
2. QLoRA 没训练新增 SID embedding：loss 可能下降很慢，生成 SID 可能一直不稳定。
3. 默认 trainer 是 CPU：不显式 override 会浪费时间或直接跑不动。
4. base model 路径无效：当前配置里的 macOS 路径必须替换。
5. 混合 `val/loss` 误导 checkpoint 选择：item-title mapping loss 下降不代表推荐能力提升。
6. 无约束生成非法 SID：训练 loss 正常，但 HR/NDCG 几乎为 0。
7. prompt 左截断不可控：title history 长时可能丢 instruction 或早期偏好，导致训练分布混乱。
8. SID 长度不是论文固定 3 token：当前 4-5 token，decode/eval/RL 都必须动态读取 index。
9. SID health warning 被忽略：dedup fallback 解决唯一性，不等于语义码没有碰撞。
10. 24GB 显存照搬论文配置会 OOM：论文 SFT 是 8 张 H100，每卡 128 samples，当前机器不能照搬。

## 推荐执行顺序

1. 修正 local model path、GPU trainer、Makefile SFT target。
2. 跑 tokenizer/SID 原子性 smoke test。
3. 跑 datamodule sample/length/task-count sanity check。
4. 跑 `new_token_only` 小样本 smoke，确认 forward/backward/checkpoint/export 正常。
5. 修 QLoRA 的新增 SID embedding 训练问题。
6. 跑 QLoRA 小样本 overfit，确认 recommendation task loss 能明显下降。
7. 实现 recommendation-only validation loss。
8. 实现 constrained beam search + HR/NDCG eval。
9. 再开正式 SFT。
10. 正式 SFT 后再考虑 RL/GRPO。

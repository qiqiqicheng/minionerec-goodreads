# Implementation Risks And TODOs

Context: current project has data preprocessing, raw EDA, item embedding, RQ-VAE, SID generation, SFT skeleton, and loss-only eval. SFT and RL have not been run end-to-end. This file is prioritized for correctness, interview defensibility, and avoiding wasted GPU time.

## P0 Must Fix Before Trusting Results

### 1. Add RQ-VAE codebook utilization monitoring

Risk: RQ-VAE codebook collapse is the most likely reproduction failure and an almost guaranteed interview question. Current `RQVAEModule` logs only `total_loss`, `recon_loss`, and `rq_loss`; it does not log per-level usage, dead codes, entropy, perplexity, or collision rate. A low reconstruction loss can still hide bad SIDs if most items use a tiny subset of codes.

Where:
- `src/minionerec_goodreads/models/rqvae.py`
- `src/minionerec_goodreads/scripts/rqvae/generate_sid.py`

Required checks:
- Per code level `l`: used codes / codebook size, dead codes, max bucket share, entropy, perplexity.
- Full code path: unique paths / num_items, collisions, top duplicated paths.
- Compare train-time `use_sk=True` assignment with inference `use_sk=False` argmin assignment.
- Save a small JSON report next to `goodreads.index.json`, e.g. `goodreads.sid_stats.json`.

Good interview answer target:
- "I do not just look at reconstruction loss. I check utilization/perplexity at each residual level and final SID collision rate. If utilization is low, SIDs become near-arbitrary coarse clusters and the LLM recommendation task loses item discrimination."

Concrete fix:
- In validation, aggregate `indices` from all batches and log `code_usage_l{0,1,2}` and `perplexity_l{0,1,2}`.
- In `generate_sid.py`, after generating all item codes, compute code path collision stats and per-level histograms.
- Treat high collision or low level usage as a failed tokenizer run, not as a harmless warning.

### 2. Fix RQ-VAE input dimension mismatch

Risk: current Qwen3 embedding artifact is `(15766, 2560)`, but `src/minionerec_goodreads/configs/model/rqvae.yaml` sets `in_dim: 768`. Training RQ-VAE on the existing embedding file will fail or silently require an incompatible artifact.

Where:
- `data/processed/rqvae/goodreads.emb-bge.npy`
- `src/minionerec_goodreads/configs/model/rqvae.yaml`
- `src/minionerec_goodreads/configs/text2emb.yaml`

Concrete fix:
- Set `model.rqvae.in_dim: 2560` for Qwen3-Embedding-4B embeddings, or explicitly add a projection/PCA step and document it.
- Add an early shape check in the RQ-VAE datamodule/model instantiation path: embedding dim must equal `cfg.model.rqvae.in_dim`.

### 3. Reconcile processed CSV schema with current SFT code

Risk: existing processed CSV files use older column names such as `history_item_id` and `history_item_title`, while current `sft_dataset.py` expects `history_item_ids` and `history_titles`. SFT will fail immediately with `KeyError` unless data is regenerated or the loader supports the current artifact schema.

Where:
- `data/processed/rqvae/train.csv`
- `src/minionerec_goodreads/scripts/rqvae/data_preprocess.py`
- `src/minionerec_goodreads/dataset/sft_dataset.py`

Concrete fix:

- If keeping old artifacts, add a deliberate schema migration, not ad-hoc aliases hidden in SFT code.
- Add a header validation error that prints expected and actual columns.

### 4. Fix `uv.lock` / Makefile execution before relying on commands

Risk: Makefile targets use `uv sync` / `uv run`, but `uv run` currently fails while parsing `uv.lock` because `bitsandbytes==0.48.2` references `torch==2.8.0` without a locked package. This makes `make data`, `make eda`, `make embedding`, and future train commands unreliable.

Where:
- `uv.lock`
- `pyproject.toml`
- `Makefile`

Concrete fix:
- Regenerate or repair `uv.lock` under the intended dependency groups.
- Verify `make data`, `make eda`, and a tiny Python import smoke test with `uv run`.
- Do not debug model code through `.venv/bin/python` only; the project contract says uv + Makefile.

Where:

### 6. Do not use default RQ-VAE callbacks without overriding monitor

Risk: default callbacks monitor `val/acc`, but RQ-VAE logs `val/total_loss`, `val/recon_loss`, and `val/rq_loss`. Running without `experiment=rqvae_goodreads` or callback override can crash checkpointing/early stopping or select no useful checkpoint.

Where:
- `src/minionerec_goodreads/configs/callbacks/default.yaml`
- `src/minionerec_goodreads/configs/experiment/rqvae_goodreads.yaml`
- `src/minionerec_goodreads/models/rqvae.py`

Concrete fix:
- For RQ-VAE, always monitor `val/total_loss` with `mode=min`.
- Consider making `train_rqvae.yaml` default to an RQ-VAE-specific callback config to avoid accidental `val/acc`.

## P1 Fix Before Reporting Paper-Level Metrics

### 7. Validate item embedding method, normalization, and duplicates

Risk: `text2emb.py` manually mean-pools `last_hidden_state` and saves unnormalized vectors. Qwen embedding models often have recommended pooling/normalization conventions. Existing embedding norms are large and varied; there are `15279 / 15766` unique embeddings, so 487 items share duplicate vectors. This can worsen RQ-VAE collapse or SID collisions.

Where:
- `src/minionerec_goodreads/scripts/rqvae/text2emb.py`
- `notes/routine.md`

Concrete checks:
- Compare current mean pooling against the model's recommended encode/pooling path.
- Save norm summary and duplicate-text/duplicate-embedding examples.
- Try L2-normalized embeddings for RQ-VAE and compare codebook usage/collisions.

### 8. `text2emb.py` ignores configured device

Risk: config has `device: "cuda:5"`, but the script uses `Accelerator()` and `accelerator.device`; `cfg.device` is currently unused. A future run may land on the wrong GPU and cause OOM or interfere with another process.

Where:
- `src/minionerec_goodreads/scripts/rqvae/text2emb.py`
- `src/minionerec_goodreads/configs/text2emb.yaml`

Concrete fix:
- Either remove `device` from config and use `CUDA_VISIBLE_DEVICES` explicitly, or wire `cfg.device` into the execution path.
- Log the actual CUDA device name and index.

### 9. RQ-VAE k-means init is fragile with current batch size

Risk: each codebook has 256 entries and RQ-VAE dataloader batch size is 256. K-means init on exactly one batch with `n_clusters=256` can be unstable, especially if duplicate/near-duplicate vectors exist. It may initialize each code to one first-batch item and not represent the global item distribution.

Where:
- `src/minionerec_goodreads/models/rqvae.py`
- `src/minionerec_goodreads/configs/data/rqvae.yaml`

Concrete fix:
- Initialize k-means on a larger sampled pool, not only the first batch.
- Ensure `kmeans_samples >> codebook_size`, e.g. several thousand item embeddings.
- Log first-batch duplicate count and k-means inertia.

### 10. Decide whether to filter target time window in preprocessing

Risk: project description says 2016-09 to 2017-12, but current preprocessing uses all read+rated interactions and only EDA reports the target window. Some anomalous timestamps remain; train split starts at 1965 and test split reaches 3103 due timestamp anomalies.

Where:
- `src/minionerec_goodreads/scripts/rqvae/data_preprocess.py`
- `notes/eda.md`

Concrete fix:
- Add optional `target_start` / `target_end` to preprocessing, or explicitly document full-history training as intentional.
- Compare row counts and metrics with and without window filtering.
- For interviews, clearly say raw timestamp anomalies exist and current split is global chronological.

### 11. Clean item text before embedding; shelves are noisy

Risk: item text includes author IDs, series IDs, and top shelves. IDs are opaque to the text encoder, and top shelves are dominated by logistics labels (`to read`, `currently reading`, `kindle`, etc.). This can pollute semantic embeddings and SIDs.

Where:
- `src/minionerec_goodreads/scripts/rqvae/data_preprocess.py`
- `notes/eda.md`

Concrete fix:
- Compare SID quality for variants:
  - title + description/review only.
  - title + description + filtered topical shelves.
  - current full text.
- Filter logistics shelves before using shelf features.
- If author/series names are unavailable, consider dropping raw IDs from item text.

### 12. Do not hide SID collisions with a fourth token

Risk: `generate_sid.py` appends a duplicate rank as a fourth token when two items share the same 3-level code. This makes every item addressable but can hide the fact that RQ-VAE failed to assign unique semantic paths. It also creates variable-length SIDs, unlike the paper's fixed 3-level SID.

Where:
- `src/minionerec_goodreads/scripts/rqvae/generate_sid.py`

Concrete fix:
- Keep the dedup fallback if needed for training, but always report raw 3-level collisions separately.
- Add an option to fail when collision rate exceeds a threshold.
- In SFT/eval, support variable-length SIDs only deliberately; do not assume all SIDs have length 3.

### 13. Implement ranking evaluation before claiming recommender quality

Risk: current `eval.py` only runs Lightning test loss. Paper-level reproduction needs generation-time HR@K and NDCG@K. Loss improvements do not prove better top-K recommendation.

Where:
- `src/minionerec_goodreads/scripts/eval.py`
- `src/minionerec_goodreads/models/sft.py`

Concrete fix:
- Build prompt -> constrained SID generation -> item lookup -> HR@3/5/10 and NDCG@3/5/10.
- Evaluate recommendation tasks separately from SID/title alignment tasks.
- Save prediction samples for qualitative debugging.

### 14. Implement constrained decoding before RL

Risk: paper's GRPO assumes the model generates valid SIDs. Without constrained decoding, RL rewards become noisy because invalid strings dominate outputs. Current repo has no SID trie or constrained generation path.

Where:
- future SFT/RL generation code
- `data/processed/rqvae/goodreads.index.json`

Concrete fix:
- Build a trie over tokenized SID sequences.
- At each generation step, mask invalid next tokens.
- Ensure beam search returns unique valid item IDs.

### 15. QLoRA likely does not train newly added SID token embeddings

Risk: in `SFTModule._build_qlora_model`, tokenizer is resized before `prepare_model_for_kbit_training` and `get_peft_model`. PEFT typically trains LoRA weights but not embedding rows unless explicitly configured. New SID embeddings may remain random/frozen, making QLoRA ineffective for SID generation.

Where:
- `src/minionerec_goodreads/models/sft.py`
- `src/minionerec_goodreads/configs/model/sft_qlora.yaml`

Concrete fix:
- Verify `requires_grad` for input/output embedding rows after QLoRA setup.
- Use `modules_to_save` or explicit trainable embedding-row masking for SID tokens.
- Add a startup log: total trainable parameters and whether SID embeddings are trainable.

### 16. SFT validation/test loss mixes recommendation and alignment tasks

Risk: `SFTDataModule` builds seq, item alignment, and fusion samples for every split. Validation loss is a mixed multitask loss, not ranking quality and not even pure next-item prediction.

Where:
- `src/minionerec_goodreads/dataset/sft_dataset.py`

Concrete fix:
- Keep mixed loss for training if desired.
- For validation/test reporting, separate losses by task or create recommendation-only eval dataloaders.
- Do not compare this mixed loss to paper HR/NDCG.

## P2 Cleanup / Robustness

### 17. SFT item alignment currently covers target items from each split, not all catalog items

Risk: `build_item_task_samples` uses `{row["item_id"] for row in rows}`. Train alignment covers train target items, not necessarily all catalog items. Valid/test alignment may include items unseen in train targets.

Where:
- `src/minionerec_goodreads/dataset/sft_dataset.py`

Concrete fix:
- For alignment tasks, consider using all item payload entries in the train split only.
- Keep recommendation rows split-specific.
- Report how many catalog items receive SID/title alignment supervision.

### 18. Token truncation happens after prompt construction

Risk: `TokenizedSFTDataset` truncates `input_ids[-max_length:]`, which can drop the instruction or beginning of the prompt for long title histories. It is better to truncate history before formatting.

Where:
- `src/minionerec_goodreads/dataset/sft_dataset.py`

Concrete fix:
- Truncate history items/titles before prompt construction based on token budget.
- Log truncation rate and average prompt length.

### 19. Check SID tokenization is truly atomic

Risk: SID strings are concatenated like `<a_1><b_2><c_3>`. `tokenizer.add_tokens` should make each SID token atomic, but this should be verified with the actual Qwen tokenizer.

Where:
- `src/minionerec_goodreads/utils/sft.py`
- `src/minionerec_goodreads/dataset/sft_dataset.py`

Concrete fix:
- Add a smoke test: encode/decode a SID string and assert it maps to exactly the expected added token IDs.
- Test variable-length collision SIDs too, e.g. `<a_1><b_2><c_3><d_2>`.

### 20. Review fallback may introduce temporal leakage

Risk: item text fallback uses all reviews, regardless of whether the review was written before the target interaction or split boundary. This is usually acceptable for transductive item metadata, but should be stated clearly.

Where:
- `src/minionerec_goodreads/scripts/rqvae/data_preprocess.py`

Concrete fix:
- Document as transductive item-content construction.
- If strict temporal evaluation is required, build fallback reviews using only pre-train-window reviews.

### 21. Check `train_rqvae.yaml` task naming and command ergonomics

Risk: `train_rqvae.yaml` uses `task_name: "train"` and generic tags. Logs/checkpoints may be hard to distinguish from other training jobs.

Where:
- `src/minionerec_goodreads/configs/train_rqvae.yaml`

Concrete fix:
- Rename task to `train_rqvae`.
- Add Makefile targets for `train-rqvae`, `generate-sid`, and `train-sft` once uv is fixed.

### 22. Add artifact sanity checks after every stage

Risk: current pipeline can produce artifacts that are syntactically present but semantically broken.

Minimum checks:
- After preprocessing: row counts, header schema, no empty histories, split target ranges.
- After embedding: shape, dtype, norm stats, duplicate count, NaN/Inf.
- After RQ-VAE: recon loss, code usage, perplexity, collisions.
- After SID generation: every item has SID, SID tokens are in tokenizer, collision fallback count.
- After SFT: trainable parameter report, task counts, sample decoded prompt/label.
- After eval: HR/NDCG plus several decoded predictions.
